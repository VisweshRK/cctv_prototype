> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reviewer dashboard at `http://localhost:1984/cctv.html`: two live cameras, a live alert feed, and a centre popup (snapshot, time, camera, area, confidence) pushed instantly. Siren alerts ring on the speaker of the camera that saw them until someone acknowledges.

**Architecture:** All backend work is in our go2rtc module `internal/cctv`:
- the event store gains updates, a subscriber fan-out and two hooks (on add, on acknowledge);
- new files add the SSE endpoint, the snapshot capture and endpoint, and the siren state machine, each behind a small function type so they can be tested without go2rtc;
- the page is plain HTML/JS in `www/` (embedded in the binary), with all of its decision logic in one ES module that Node tests directly.

**Tech Stack:** Go (go2rtc fork, `testify/require`), plain HTML/CSS/ES modules, go2rtc's `<video-stream>` player, Node 24 built-in test runner for the JS logic.

**Spec:** [docs/superpowers/specs/2026-10-19-demo-ui-design.md](../specs/2026-10-19-demo-ui-design.md). Approved look: [2026-10-19-demo-ui-mockup.html](../specs/2026-10-19-demo-ui-mockup.html).

## Review Focus

1. **A dashboard tab that stops reading** (laptop asleep, frozen tab) must never slow down `POST /api/cctv/events`. The store drops that subscriber instead. Test: Task 2 `TestSlowSubscriberIsDropped`.
2. **The snapshot grab fails or never returns** (camera offline, stream missing, no ffmpeg). The event is still stored and pushed, the grab gives up within its timeout, and the popup switches from the shimmer to "No snapshot available" after 12 s. Tests: Task 4 `TestSnapshotGrabFailureLeavesEventWithoutSnapshot`; Task 7 `snapshotState` cases.
3. **A POST carrying a broken `image`** (not base64, or not a JPEG) gets a 400 with a clear message and stores nothing. Test: Task 4 `TestPostImageRejectsBadData`.
4. **go2rtc restarts while a siren is ringing.** After the restart nothing rings, and loaded events no longer say `ringing` (otherwise the page would pop them up as if they were still ringing). Test: Task 1 `TestLoadResetsRingingAndAppliesUpdates`.
5. **Event text containing HTML** (an OCR plate like `<img onerror=…>`, a zone name with `&`) shows as text and never runs. Tests: Task 7 `esc` cases. Task 9 renders only through `esc` or `textContent`.

**Files:**

- Test: `internal/cctv/cctv_test.go` (add tests; keep the existing ones passing)

**Interfaces:**
- Produces:
  - `Event` gains `AcknowledgedAt *time.Time `json:"acknowledged_at,omitempty"`` and `Siren string `json:"siren,omitempty"``.
  - Constants `sirenRinging = "ringing"`, `sirenStopped = "stopped"`, `sirenUnavailable = "unavailable"`.
  - `type message struct { Type string; Event Event }`, where `Type` is `"alert"` (new event) or `"update"` (changed event).
  - `func (s *eventStore) get(id int64) (Event, bool)`
  - `func (s *eventStore) update(id int64, change func(e *Event)) (Event, bool)` applies `change` under the lock, appends the whole updated event as a new JSONL line, publishes `"update"`, and returns false for an unknown id.
  - `func (s *eventStore) subscribe() (<-chan message, func())` returns a channel (buffer 64) and a cancel function. Publishing never blocks: a subscriber whose buffer is full is removed and its channel closed.
  - `func (s *eventStore) oldestID() int64` returns the id of the oldest event still kept (0 when empty).
  - `func (s *eventStore) addWithImage(e Event, image []byte) (Event, error)` stores the event, publishes `"alert"`, then calls `s.onAdd(e, image)` if set. Publishing and hooks run outside the lock. `add(e)` becomes `addWithImage(e, nil)`.
  - Hook fields: `onAdd func(e Event, image []byte)` and `onAck func(e Event)`. Both are set once in `Init` before serving.
  - Loading:
    - a line whose id is already loaded replaces that event in place (that is how acknowledgements and snapshots survive restarts);
    - after loading, any event with `Siren == sirenRinging` becomes `sirenStopped`.

### Task 4: Snapshots: capture, POSTed image, endpoint and clean-up

**Files:**
- Create: `internal/cctv/snapshots.go`
- Modify: `internal/cctv/events.go` (POST: optional `image`; body limit 4 MB)

**Interfaces:**
- Consumes: `addWithImage`, `update` and `oldestID` from Task 1.
- Produces:
  - `type frameGrabber func(camera string) ([]byte, error)`
  - `type snapshots struct { dir string; grab frameGrabber; store *eventStore }`
  - `func newSnapshots(dir string, grab frameGrabber, store *eventStore) *snapshots`
  - `func (p *snapshots) handle(e Event, image []byte)` is used as `store.onAdd`. It starts a goroutine and returns at once.
    - In the goroutine: use `image` if it isn't nil, otherwise `p.grab(e.Camera)`.
    - Write `<dir>/<id>.jpg` (create the dir).
    - Then `store.update(e.ID, set Snapshot = "api/cctv/snapshot?id=<id>")`.
    - Then `p.prune(store.oldestID())`.
    - Skip the grab for labels `camera_offline` and `camera_online`, since there is no picture to take.
    - On a grab error, log at debug level and leave `Snapshot` empty.
  - `func (p *snapshots) prune(oldest int64)` deletes `<dir>/<n>.jpg` for every `n < oldest`, and ignores other files.
  - `func (p *snapshots) apiSnapshot(w http.ResponseWriter, r *http.Request)` for `GET /api/cctv/snapshot?id=<n>`.
    - Accept `id` only if it matches `^[0-9]+$`, otherwise 400.
    - Missing file: 404.
    - Otherwise 200 `image/jpeg`, `Cache-Control: max-age=86400` (a snapshot never changes).
  - `func grabFrame(camera string) ([]byte, error)` is the real grabber. It does what `internal/mjpeg/mjpeg.go` `handlerKeyframe` does:
    - `magic.NewKeyframe()`, `stream.AddConsumer`, `WriteTo` into a `core.OnceBuffer`, `RemoveConsumer`;
    - `ffmpeg.JPEGWithQuery(b, url.Values{})` for H.264/H.265, `mjpeg.FixJPEG` for JPEG;
    - a missing stream returns `errNotConfigured`;
    - it must return within `grabTimeout = 8 * time.Second`: wait on the `WriteTo` in a goroutine, and on timeout stop the consumer and return an error.
- POST change in `apiEvents`:
  - decode into `struct { Event; Image string `json:"image"` }`, with `MaxBytesReader` 4 MB (`4 << 20`);
  - a non-empty `Image` must be valid `base64.StdEncoding` whose bytes start with `0xFF 0xD8`. Otherwise 400 `{"error":"image must be a base64 JPEG"}`, checked before anything is stored;
  - call `s.addWithImage(e, imageBytes)`;
  - the image is never stored in the event and never pushed.

### Task 5: Camera siren

**Files:**
- Create: `internal/cctv/siren.go`
- Test: `internal/cctv/cctv_test.go`

**Interfaces:**
- Consumes: `update()` and `onAck` from Task 1; the siren constants.
- Produces:
  - `type sirenPlayer func(camera, source string) error`, where `source == ""` means stop.
  - `func newSiren(play sirenPlayer, source string, useCases []string, max time.Duration, store *eventStore) *siren`
  - `func (s *siren) onEvent(e Event)`: does nothing unless `e.UseCase` is in `useCases` and the event isn't acknowledged. Called from the `onAdd` chain.
  - `func (s *siren) onAck(e Event)`, used as `store.onAck`.
  - `func playOnCamera(camera, source string) error` is the real player: `streams.Get(camera)`; nil → `errNotConfigured`; else `stream.Play(source)`.
  - `func writeSirenWAV(path string) error` writes a 2 s loopable two-tone siren unless the file already exists:
    - 16-bit PCM, mono, 8000 Hz;
    - 960 Hz for 0.5 s, 770 Hz for 0.5 s, twice;
    - amplitude 0.6;
    - written in Go, so no binary file is committed.
- State per camera: `ringing`, `cutOff`, `warned` (the unavailable log line has been written), `pending` (set of unacknowledged siren event ids), and a timer.
  - **New siren event**, added to `pending`:
    - if neither ringing nor cut off: `play(cam, source)`.
      - Error: the event becomes `Siren = unavailable`, logged once per camera at warn level ("camera speaker not available").
      - OK: `ringing = true`, start a `max` timer, event becomes `ringing`.
    - Already ringing: the event becomes `ringing`, and the timer is **not** restarted.
    - Cut off: the event becomes `stopped`.
  - **Timer fires**: `play(cam, "")`, `ringing = false`, `cutOff = true`, every pending event becomes `stopped`.
  - **Ack**: remove the id from `pending`. When `pending` is empty: if ringing, `play(cam, "")` and stop the timer; then `ringing = false` and `cutOff = false`.
  - `play` is never called while the siren mutex is held, because it can block while dialling the camera. Decide under the lock, call `play` outside it, then record the result.

### Task 7: Dashboard logic module (no DOM)

**Files:**
- Create: `www/cctv-logic.js` (ES module), `www/tests/cctv-logic.test.mjs`. The tests folder isn't embedded, because the embed only matches top-level files.

**Interfaces:**
- Produces (all exported):
  - `USE_CASES`: the spec table, one entry per `use_case` with `{severity, title, siren}`. Popup rules by label:
    - `tampering`/`camera_online` → info, "Camera back online", feed only;
    - `face_recognition`/`known_face` → info, `Known: {data.name}`, feed only; `unknown_face` → medium, "Unknown person", popup;
    - `vehicle_lpr`/`plate` → info, `Vehicle · {data.plate}`, popup; `vehicle_lpr`/`vehicle` (no plate read) → info, "Vehicle", feed only;
    - `occupancy` → feed only;
    - an unknown `use_case` → info, the raw use case as title, feed only.
  - `describe(e) -> {severity: "critical"|"high"|"medium"|"info", title: string, popup: boolean, siren: boolean}`
  - `areaOf(e) -> string`: `data.area` || `data.zone` || `"Whole view"`.
  - `detailOf(e) -> string`: `data.detail` if set, else built from label and data (e.g. `"person · Server room door"`).
  - `boxOf(e) -> [x1, y1, x2, y2] | null`: only when `data.box` holds 4 numbers in 0..1 with `x1 < x2`, `y1 < y2`.
  - `esc(s) -> string` escapes `& < > " '`.
  - `snapshotState(e, now) -> "ready" | "loading" | "none"`: `ready` if `e.snapshot`; `loading` if less than 12 s since `e.time`; else `none`.
  - `class Incidents` is the popup queue.
    - `add(e)` keeps only popup events that aren't acknowledged, grouped by `camera|use_case`. A new event joins its group and makes the group the newest.
    - `update(e)` replaces the event by id; an acknowledged event leaves its group, and an empty group is removed.
    - `current() -> {key, camera, useCase, events, latest} | null` is the most recently updated group.
    - `others() -> number` is the count of the other groups.
    - `ids(key) -> number[]`.
